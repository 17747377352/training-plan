## 已知设计约束

- **MFA 会话不能放进 Redis。** `python-garminconnect` 的 `resume_login(client_state, mfa_code)` 需要一个存活的客户端对象，`client_state` 不可序列化。会话因此保存在 Collector 进程内存（`MfaSessionStore`，TTL 600 秒、上限 100 个），Redis 只存「会话 ID → 账号 ID」映射用于归属校验。**Collector 首期必须单副本部署**，或对 `loginSessionId` 做粘性路由，否则提交验证码的请求可能落到没有该会话的副本。
- **Token 加密密钥必须备份。** `app.security.token-cipher-key` 丢失后已存储的 Garmin Token 无法解密，所有账号都需要重新认证。
- **禁用用户的即时性。** access token 是无状态的，禁用后最长 15 分钟内仍能通过签名校验；但 `login`、`refresh` 和 `UserService.getProfile` 都会检查状态，因此禁用用户无法登录、无法续期，业务接口也会被拒。新增业务接口时需沿用"读取用户状态"的做法。
- **首个管理员需人工提升。** 注册只分配 `USER` 角色，平台未提供创建管理员的接口，需在数据库中手动授予 `ADMIN`。
- **删除账号暂不级联删除同步数据。** `sync_job` 对 `garmin_account` 有外键约束，目前没有同步数据所以删除可用；接入同步后需要在同一事务里先清理同步数据。
